Software Quality

Software quality is the degree to which a product meets stated requirements and user needs. ISO/IEC 25010 (2011) models it through eight characteristics. Testing is the main activity that gathers evidence about them (Pressman & Maxim, 2020).

Finding defects early matters: the later a fault is found, the more it costs to fix (Boehm, 1981).

02

Testing Fundamentals

Testing is executing a program with the intent of finding errors (Myers et al., 2011). A test case pairs an input and precondition with an expected result; a mismatch reveals a failure caused by a fault.

Testing can show the presence of bugs, never their absence (Dijkstra, 1970), and exhaustive testing is impractical, so tests must be chosen strategically.

Example: for a login form, input “valid user, wrong password” should expect “access denied”.

Verification vs. Validation

“Are we building the product right?” Checks that work products conform to their specification through reviews, inspections and static analysis (Boehm, 1981).

“Are we building the right product?” Checks that the software satisfies real user needs by executing it against customer expectations (Sommerville, 2016).

03

Black-Box & White-Box Testing

Black-box testing derives tests from the specification (inputs and outputs only), using techniques such as equivalence partitioning and boundary value analysis. White-box testing derives tests from the code structure. Basis-path testing measures cyclomatic complexity V(G) = P + 1, where P is the number of predicate conditions, and exercises each independent path (McCabe, 1976; Pressman & Maxim, 2020).
